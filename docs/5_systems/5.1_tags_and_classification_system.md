# 5.1 Система тегов и классификации

**Определение:** Система маркировки акторов через теги с категориями и политиками для автоматической валидации совместимости и булевой классификации объектов.

### Базовые концепции

### Тег (Tag)

**Определение:** ScriptableObject, представляющий конкретное свойство или состояние, которое может быть присвоено актору.

**Tag структура:**
```
Tag : ScriptableObject {
    id: string                          // Уникальный строковый идентификатор
    category: TagCategoryDefinition     // Ссылка на категорию
    displayName: string                 // Название для UI
    description: string                 // Описание для разработчиков
}
```

**Строковое представление:** Каждый тег имеет строковый ID для удобства использования в коде и конфигурации.

### Категория тегов (TagCategory)

**Определение:** Группа тегов с общими правилами поведения и валидации.

**TagCategoryDefinition структура:**
```
TagCategoryDefinition : ScriptableObject {
    categoryId: string                  // Уникальный идентификатор категории
    quantityPolicy: QuantityPolicy      // Single или Multiple
    mutabilityPolicy: MutabilityPolicy  // Mutable или Immutable
    displayName: string                 // Название для UI
    description: string                 // Описание назначения категории
}
```

### Политики категорий

### Политики количества (QuantityPolicy)

### Single (единичная политика)

**Поведение:** В категории может быть только один активный тег. При добавлении нового тега старый автоматически удаляется.

**Применение:** Для взаимоисключающих свойств
- Категория "size": tiny, small, medium, large, huge
- Категория "life_state": alive, dead, unconscious

**Пример поведения:** тег `size:small` + тег `size:large` → остается `size:large`

### Multiple (множественная политика)

**Поведение:** В категории может быть несколько активных тегов одновременно.

**Применение:** Для накапливающихся или независимых свойств
- Категория "resistance": fire_resistant, cold_resistant, magic_resistant
- Категория "material": organic, mechanical, magical

**Пример поведения:** тег `resistance:fire_resistant` + тег `resistance:cold_resistant` → остаются оба

### Политики изменяемости (MutabilityPolicy)

### Immutable (неизменяемый)

**Поведение:** Теги этой категории нельзя изменять после инициализации актора.

**Применение:** Для базовых неизменяемых свойств
- Категория "type": humanoid, beast, construct, undead
- Категория "base_material": organic, mechanical, ethereal

### Mutable (изменяемый)

**Поведение:** Теги можно свободно добавлять/удалять в процессе игры.

**Применение:** Для динамических состояний
- Категория "temporary_state": stunned, poisoned, blessed
- Категория "equipment_bonus": armored, armed, enchanted

### Техническая реализация

### Компоненты системы

**TagManager** - основной компонент системы:
- Управление регистрацией категорий тегов
- Предоставление API для работы с тегами акторов
- Валидация операций с тегами

**ActorTagContainer** - компонент актора:
- Хранение тегов конкретного актора
- Организация тегов по категориям
- Кэширование для быстрого доступа

**TagCategoryRegistry** - реестр категорий:
- Словарь зарегистрированных категорий
- Валидация определений категорий
- Предоставление информации о политиках

### Структуры данных

### ActorTagContainer структура

**Хранение тегов актора:**
```
ActorTagContainer : MonoBehaviour {
    tagsByCategory: Dictionary<string, HashSet<Tag>>     // Теги по категориям
    allTagsCache: HashSet<Tag>                           // Кэш всех тегов для быстрого поиска
    tagLookupCache: Dictionary<string, Tag>              // Быстрый поиск по ID
    isInitialized: bool                                  // Завершена ли инициализация
}
```

### TagCategoryRegistry структура

**Реестр категорий:**
```
TagCategoryRegistry : ScriptableObject {
    categories: Dictionary<string, TagCategoryDefinition>  // Категории по ID
    defaultCategories: List<TagCategoryDefinition>         // Базовые категории системы
}
```

### Алгоритм валидации

### Валидация при добавлении тега

**Последовательность проверок:**
1. **Проверка Tag ScriptableObject** - тег не должен быть null, категория должна быть назначена
2. **Валидация Immutable** - если категория Immutable и актор инициализирован, отклонить
3. **Применение политики Single** - если Single, удалить существующие теги той же категории
4. **Проверка дублирования** - предотвратить добавление уже существующего тега (по Tag.id)
5. **Добавление тега** - добавить в tagsByCategory и обновить кэши

### Валидация при удалении тега

**Последовательность проверок:**
1. **Проверка существования тега** - тег должен присутствовать у актора
2. **Валидация Immutable** - если категория Immutable и актор инициализирован, отклонить
3. **Удаление тега** - удалить из tagsByCategory и обновить кэши

### Инициализация системы

### Загрузка категорий

**Процесс инициализации TagManager:**
1. **Загрузка TagCategoryRegistry** - получение списка категорий от разработчика
2. **Валидация определений** - проверка уникальности categoryId и корректности политик
3. **Регистрация категорий** - создание словаря для быстрого доступа O(1)
4. **Инициализация базовых категорий** - создание стандартных категорий если они не заданы

### Инициализация ActorTagContainer

**Процесс инициализации актора:**
1. **Получение начальных тегов** - список Tag ScriptableObjects из Inspector или TagProfile
2. **Валидация тегов** - проверка что все Tag объекты имеют назначенные категории
3. **Применение политик** - разрешение конфликтов Single категорий
4. **Построение кэшей** - создание tagLookupCache для быстрого поиска по ID
5. **Установка isInitialized = true** - блокировка изменений Immutable категорий

### API системы

### Основные методы TagManager

**Управление категориями:**
- `TagManager.RegisterCategory(TagCategoryDefinition category)` → bool
- `TagManager.GetCategory(string categoryId)` → TagCategoryDefinition
- `TagManager.IsCategoryRegistered(string categoryId)` → bool

**Глобальные операции:**
- `TagManager.FindActorsWithTag(Tag tag)` → List<Actor>
- `TagManager.FindActorsWithAllTags(List<Tag> tags)` → List<Actor>
- `TagManager.ValidateTagOperation(Actor actor, Tag tag, TagOperation operation)` → ValidationResult

### Основные методы ActorTagContainer

**Управление тегами:**
- `ActorTagContainer.AddTag(Tag tag)` → bool
- `ActorTagContainer.RemoveTag(Tag tag)` → bool
- `ActorTagContainer.HasTag(Tag tag)` → bool
- `ActorTagContainer.HasTagById(string tagId)` → bool

**Получение тегов:**
- `ActorTagContainer.GetTagsInCategory(string categoryId)` → HashSet<Tag>
- `ActorTagContainer.GetAllTags()` → HashSet<Tag>
- `ActorTagContainer.GetCategoriesWithTags()` → List<string>

### Результаты операций

**ValidationResult:**
```
ValidationResult {
    isValid: bool
    errorType: TagErrorType      // CategoryNotFound, ImmutableViolation, DuplicateTag
    message: string              // Описание ошибки для отладки
}
```

**TagErrorType enum:**
- `Success` - операция успешна
- `CategoryNotFound` - категория не зарегистрирована
- `ImmutableViolation` - попытка изменить Immutable категорию
- `DuplicateTag` - попытка добавить уже существующий тег
- `TagNotFound` - попытка удалить несуществующий тег

### События системы

**События изменения тегов:**
- **OnTagAdded** - тег добавлен к актору
- **OnTagRemoved** - тег удален у актора
- **OnCategoryRegistered** - новая категория зарегистрирована

**Структура события:**
```
TagEvent {
    actor: Actor
    tag: Tag                    // ScriptableObject тега
    operation: TagOperation     // Add, Remove
    timestamp: float
}
```

### Примеры использования

### Конфигурация категорий и тегов

**Категория типов (Single + Immutable):**
```
TypeCategory: {
    categoryId: "type"
    quantityPolicy: Single
    mutabilityPolicy: Immutable
}

Теги в категории:
- HumanoidTag: { id: "humanoid", category: TypeCategory }
- BeastTag: { id: "beast", category: TypeCategory }
- ConstructTag: { id: "construct", category: TypeCategory }
- UndeadTag: { id: "undead", category: TypeCategory }
```

**Категория состояний (Single + Mutable):**
```
LifeStateCategory: {
    categoryId: "life_state"
    quantityPolicy: Single
    mutabilityPolicy: Mutable
}

Теги в категории:
- AliveTag: { id: "alive", category: LifeStateCategory }
- DeadTag: { id: "dead", category: LifeStateCategory }
- UnconsciousTag: { id: "unconscious", category: LifeStateCategory }
```

**Категория сопротивлений (Multiple + Mutable):**
```
ResistanceCategory: {
    categoryId: "resistance"
    quantityPolicy: Multiple
    mutabilityPolicy: Mutable
}

Теги в категории:
- FireResistantTag: { id: "fire_resistant", category: ResistanceCategory }
- ColdResistantTag: { id: "cold_resistant", category: ResistanceCategory }
- MagicResistantTag: { id: "magic_resistant", category: ResistanceCategory }
```

### Ограничения и особенности

**Архитектурные решения:**
- Tag и TagCategoryDefinition как ScriptableObjects для удобства настройки в редакторе
- Хранение ссылки на категорию в теге вместо CategoryID исключает необходимость валидации существования
- Тройное кэширование в ActorTagContainer: по категориям, общий кэш, поиск по ID
- Разделение политик количества и изменяемости для большей гибкости

**Текущие ограничения:**
- Статический набор категорий (регистрируются при инициализации)
- Tag ScriptableObjects должны быть созданы в редакторе заранее
- Теги представляют только булевые свойства (есть/нет), без дополнительных значений
