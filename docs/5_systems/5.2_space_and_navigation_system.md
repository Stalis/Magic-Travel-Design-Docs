# 5.2 Система пространства и навигации

**Определение:** Система пространственной организации игрового мира через дискретную сетку клеток с геймплейными свойствами и навигационными возможностями, независимыми от визуального представления.

### Зависимости
- **Использует системы:** Нет (фундаментальная система)
- **Используется системами:** 5.7 (Ходы), 5.8 (Действия), 6.1 (Механика боя)

### Предоставляет другим системам
- Валидация перемещения и проходимости
- Трассировка прямых путей (видимость, полет снарядов)
- Расчет расстояний между точками
- Поиск соседних клеток с условиями
- Пространственные запросы и проверки

### Структура системы

### Иерархия компонентов Unity

**Компоненты карты:**
1. **Map** - корневой компонент уровня, управляет инициализацией
2. **Location** - компонент крупной области карты 
3. **Room** - компонент логического контейнера внутри локации
4. **Cell** - компонент минимальной единицы пространства с координатами
5. **Wall** - компонент барьера между клетками по четырем направлениям

### Система Data-компаньонов

**ScriptableObject структуры:**
- **MapData** - данные карты без привязки к компонентам
- **LocationData** - данные локации
- **RoomData** - данные комнаты  
- **CellData** - данные клетки
- **WallData** - данные стены

**Создание Data объектов:**
- **Вручную разработчиком** - для настраиваемых сущностей
- **Автоматически в Awake** - для стандартных сущностей на основе настроек компонента

### Инициализация системы

#### Процесс загрузки карты

**Алгоритм инициализации:**
1. **Триггер загрузки** - в данный момент Start компонента Map, в будущем система загрузки уровня
2. **Сканирование структуры** - Map проходится по всей иерархии дочерних объектов
3. **Сбор данных** - извлечение Data объектов и настроек компонентов
4. **Создание MapRegistry** - построение словаря с координатами как ключами
5. **Валидация** - проверка целостности и корректности данных

**После инициализации:**
- Компоненты используются только для отладки и визуализации в редакторе
- Вся игровая логика работает через MapRegistry

### MapRegistry структура

#### Основной словарь

**Техническая реализация:**
```
MapRegistry: ScriptableObject {
    cells: Dictionary<Vector2Int, CellRegistry>
}
```

**Ключи координат:**
- **Vector2Int** - стандартный Unity тип для целочисленных 2D координат
- Прямой доступ O(1) к любой клетке по координатам

### CellRegistry структура

**Содержимое записи:**
```
CellRegistry {
    // Параметры клетки (ScriptableVariable ссылки)
    isWalkable: ScriptableVariable<bool>
    isTransparent: ScriptableVariable<bool>
    isPiercable: ScriptableVariable<bool>
    
    // Параметры 4х прилегающих стен (по сторонам света)
    northWall: WallProperties (ScriptableVariable ссылки)
    eastWall: WallProperties (ScriptableVariable ссылки)
    southWall: WallProperties (ScriptableVariable ссылки)
    westWall: WallProperties (ScriptableVariable ссылки)
}
```

**Динамические изменения:**
- Свойства хранятся как ссылки на ScriptableVariable
- Изменение переменной автоматически влияет на игровую логику
- Позволяет реализовать двери, ловушки, временные препятствия
- Примеры: дверь меняет walkable/transparent/piercable по событию

### Система координат

**Направления стен:**
- **North** - верхняя граница клетки
- **East** - правая граница клетки  
- **South** - нижняя граница клетки
- **West** - левая граница клетки

### Свойства элементов

#### Свойства клеток

**isWalkable** - проходимость для движения:
- `true`: актор может занимать эту клетку
- `false`: клетка заблокирована для движения

**isTransparent** - прозрачность для обзора:
- `true`: через клетку проходит линия видимости
- `false`: клетка блокирует обзор

**isPiercable** - проницаемость для снарядов:
- `true`: через клетку могут проходить дистанционные атаки
- `false`: клетка блокирует снаряды

#### Свойства стен

**Стены используют те же свойства** с аналогичной логикой:
- **isWalkable**: можно ли пройти через стену (двери)
- **isTransparent**: блокирует ли стена обзор
- **isPiercable**: можно ли стрелять через стену

**Примеры конфигураций:**
- Открытый проход: `walkable=true, transparent=true, piercable=true`
- Дверь: `walkable=true, transparent=false, piercable=false`
- Решетка: `walkable=false, transparent=true, piercable=false`

### API MapRegistry

#### Методы реестра

**Получение свойств:**
- `MapRegistry.GetCellProperty(Vector2Int coordinates, property)` - свойство клетки
- `MapRegistry.GetWallProperty(Vector2Int coordinates, Direction direction, property)` - свойство стены
- `MapRegistry.IsWalkable(Vector2Int coordinates)` - быстрая проверка проходимости
- `MapRegistry.IsTransparent(Vector2Int coordinates)` - быстрая проверка прозрачности

**Пространственные операции:**
- `MapRegistry.GetAdjacentCells(Vector2Int coordinates)` - соседние клетки
- `MapRegistry.HasCell(Vector2Int coordinates)` - существует ли клетка с такими координатами

### Ограничения и особенности

**Архитектурные решения:**
- Разделение компонентов Unity и игровых данных
- Инициализация структуры карты при загрузке уровня
- Динамические изменения свойств через ScriptableVariable

**Текущие ограничения:**
- Структура карты (координаты клеток/стен) статична после инициализации
- Нельзя добавлять/удалять клетки или стены во время игры
- Можно изменять только свойства существующих элементов

## Навигационные возможности

### Валидация перемещения

**Ортогональное перемещение:**
- Проверка проходимости всех клеток и стен на пути
- Поддержка перемещения на 1-2 клетки в одном направлении
- Учет состояния клеток и стен по различным критериям

**API методы:**
- `CanMoveTo(from, to)` - основная валидация перемещения
- `CanMoveToWithCondition(from, to, condition)` - с кастомными условиями
- `ValidateMovementPath(path)` - проверка многошагового пути

### Трассировка прямых путей

**Назначение:**
- Линия видимости между акторами
- Полет снарядов для дальних атак
- Наведение мышью и прицеливание
- Проверка просветов и обструкций

**Алгоритм для игры от первого лица:**

**1. Grid Traversal + Wall Checking:**
```
Пример: луч из (1,0) в (5,4)
  0 1 2 3 4 5    . - пустая клетка
0 . S . . . .    o - препятствие
1 . o \ . . .    S - источник
2 . . . \ o .    E - цель
3 . . . . \ .    \ - луч
4 . . . . . E

Алгоритм:
1. Получаем все клетки на пути: (1,0) → (2,0) → (2,1) → (3,1) → (3,2) → (4,2) → (4,3) → (5,3) → (5,4)
2. Для каждой пары соседних клеток проверяем стену между ними
3. Проверяем каждую клетку на пути
4. При переходе (2,0) → (2,1): проверяем северную стену (2,0)
5. При переходе (2,1) → (3,1): проверяем восточную стену (2,1)
6. Клетка (2,1) не проходима → луч заблокирован
```

**Особенности для FPS-подобной игры:**
- Нельзя "заглянуть" за угол - строгая проверка линии видимости
- Любое препятствие на пути блокирует стрельбу и магию
- Наведение мышью следует тем же правилам
- Проверка каждой клетки и каждой стены на пути

**2. Bresenham Line (для UI и предварительных проверок):**
- Быстрая аппроксимация линии
- Используется для отображения траектории в UI
- Не гарантирует корректность для геймплейных проверок

**API методы:**
- `TraceLine(from, to, condition)` - основная трассировка (Grid Traversal + Wall Checking)
- `HasLineOfSight(from, to)` - проверка видимости (строгая)
- `CanShootThrough(from, to)` - проверка для стрельбы (строгая)
- `CanCastSpellThrough(from, to)` - проверка для магии (строгая)
- `GetProjectileImpact(from, to)` - точка попадания снаряда
- `GetLineForUI(from, to)` - линия для отображения (Bresenham)

### Расчет расстояний

**Метрика расстояния:**
- **Euclidean** - прямое расстояние для всех игровых механик

**Применение:**
- Радиус заклинаний и аур
- Дальность стрельбы и атак
- Зоны эффектов и влияния
- Проверка доступности целей
- Расчет урона от расстояния (для взрывов)

**API методы:**
- `GetDistance(from, to)` - евклидово расстояние
- `IsWithinRange(from, to, range)` - проверка на дистанцию
- `GetClosestPoint(from, targets)` - ближайшая цель
- `GetTargetsInRange(from, range, targets)` - все цели в радиусе

### Поиск соседних клеток

**API методы:**
- `GetNeighbors(cell, condition = null)` - соседи с опциональной фильтрацией
- `GetWalkableNeighbors(cell)` - только проходимые соседи
- `GetEmptyNeighbors(cell)` - свободные клетки (без акторов)

### Оптимизация навигации

**Производительность:**
- Кэширование результатов сложных вычислений
- Оптимизация алгоритмов трассировки
- Bresenham для UI, Grid Traversal для геймплея
- Предварительный расчет часто используемых путей

**Особенности для FPS-подобной игры:**
- Строгая проверка линии видимости (нельзя "заглянуть" за угол)
- Каждое препятствие на пути блокирует луч
- Проверка всех клеток и стен на траектории
- Наведение мышью следует тем же правилам

**Ограничения навигации:**
- Работает только с ортогональным движением по сетке
- Нет поиска сложных путей (A*) - это отдельная система
- Не учитывает динамические препятствия (другие акторы)
- Все проверки основаны на свойствах клеток и стен
