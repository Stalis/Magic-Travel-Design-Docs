# 5.4 Система действий

### Основные принципы

**Определение:** Действием является любая активность, которую может выполнить актор: от простого движения до сложных заклинаний.

### Структура действия

**Компоненты действия:**
1. **Исполнитель** - актор, выполняющий действие
2. **Цель** - Action Target для применения действия (может отсутствовать)
3. **Параметры** - дополнительные данные для выполнения
4. **Базовая стоимость ресурсов** - требуемые ресурсы по типам (основные ОД, дополнительные ОД, мана, здоровье и т.д.)

**Расчет финальной стоимости:**
Финальная стоимость действия рассчитывается путем применения всех активных модификаторов к базовой стоимости:
- Способности актора (снижение стоимости определенных действий)
- Активные баффы/дебаффы (например, состояние “усталость” увеличивает расход очков действий)
- Состояние экипировки (поврежденное оружие может требовать больше усилий)
- Особые условия окружения (заклинания в зоне антимагии стоят дороже)

**Пример расчета:**

```
Заклинание "Огненный шар":
- Базовая стоимость: 2 маны, 1 ООД
- Состояние "Магическое истощение": удваивает расход маны
- Способность "Эффективное колдовство": -1 к стоимости маны
- Финальная стоимость: (2 × 2) - 1 = 3 маны, 1 ООД
```

**Процесс выполнения действия:**
- Каждое действие определяет базовую стоимость для всех типов ресурсов
- При выполнении система применяет все активные модификаторы для расчета финальной стоимости
- Система ресурсов проверяет наличие всех необходимых ресурсов
- При успешной валидации ресурсы списываются одной операцией

### Валидация действий

**Принципы валидации:**
Система действий использует [Систему тегов и классификации](about:blank#%D1%81%D0%B8%D1%81%D1%82%D0%B5%D0%BC%D0%B0-%D1%82%D0%B5%D0%B3%D0%BE%D0%B2-%D0%B8-%D0%BA%D0%BB%D0%B0%D1%81%D1%81%D0%B8%D1%84%D0%B8%D0%BA%D0%B0%D1%86%D0%B8%D0%B8) для автоматической проверки совместимости действий и целей.

**Определение требований к действиям:**
Каждое действие может задавать требования к базовым характеристикам и свободным тегам Action Target:

```
Действие: "Воскрешение"
- requires_life_state: Dead
- excludes_type: Undead, Construct

Действие: "Атака мечом"
- requires_physical_form: Corporeal
- excludes_allegiance: Ally (опционально)

Действие: "Лечение"
- requires_life_state: Alive
- requires_free_tags: organic
- excludes_type: Undead, Construct
```

### Процесс валидации

### Процесс валидации

**Система проверок (выполняется последовательно):**

1. **Валидация совместимости** (автоматическая для всех действий):
    - Проверка базовых характеристик цели через систему классификации
    - Проверка свободных тегов цели
    - Проверка совместимости типов сущностей
2. **Проверка доступности действия для исполнителя**:
    - Наличие необходимых способностей
    - Соответствие уровня и класса
3. **Проверка наличия всех необходимых ресурсов**:
    - Расчет финальной стоимости с учетом модификаторов
    - Проверка каждого типа ресурса (очки действий, энергия, предметы)
4. **Кастомная валидация действия** (опциональная):
    - Специфические правила для конкретных действий
    - Контекстуальные проверки (время суток, местоположение)
5. **Проверка игровых условий и ограничений**:
    - Ограничения локации или события
    - Временные глобальные эффекты

**Процесс выполнения:**
1. Получение базовой стоимости действия
2. Применение всех модификаторов стоимости
3. **Резервирование ресурсов** - временная заморозка необходимых ресурсов без их списания
4. Финальная валидация перед выполнением
5. Выполнение действия
6. Списание зарезервированных ресурсов (или их разблокировка при отмене)

**Назначение резервирования:**
- **Техническая безопасность:** предотвращает случайное двойное списание ресурсов при багах или прерываниях
- **Обратная связь для игрока:** UI может показать реальную стоимость действия до его выполнения
- **Предварительная валидация:** позволяет игроку выбрать действие, навестись на цель, но передумать без потери ресурсов
- Работает как для игроков, так и для AI-сущностей

### Практические примеры валидации

### Пример 1: Неуспешная валидация по совместимости

**Сценарий:** Игрок пытается использовать заклинание “Лечение” на Скелете-воине

**Пошаговая валидация:**
1. **Выбор действия:** “Лечение” (requires_life_state: Alive, excludes_type: Undead)
2. **Цель:** “Скелет-воин” (Dead, Undead, Corporeal, Enemy)
3. **Валидация совместимости:**
- requires_life_state: Alive → цель Dead ❌
- excludes_type: Undead → цель Undead ❌
4. **Результат:** Валидация прерывается на первом шаге
5. **UI-отклик:** “Нельзя лечить нежить”, действие недоступно для выбора

### Пример 2: Неуспешная валидация по ресурсам

**Сценарий:** Маг с 1 маной пытается кастовать “Огненный шар”

**Пошаговая валидация:**
1. **Выбор действия:** “Огненный шар” (базовая стоимость: 2 маны, 1 ООД)
2. **Цель:** “Гоблин” (Alive, Humanoid, Corporeal, Enemy)
3. **Валидация совместимости:** ✅ (нет особых требований)
4. **Проверка доступности:** ✅ (маг знает заклинание)
5. **Расчет финальной стоимости:**
- Базовая: 2 маны, 1 ООД
- Модификаторы: нет
- Финальная: 2 маны, 1 ООД
6. **Проверка ресурсов:**
- Нужно: 2 маны → доступно: 1 мана ❌
- Нужно: 1 ООД → доступно: 1 ООД ✅
7. **Результат:** Валидация провалена на этапе ресурсов
8. **UI-отклик:** “Недостаточно маны (нужно 2, есть 1)”, действие заблокировано

### Пример 3: Успешная валидация с резервированием

**Сценарий:** Воин атакует гоблина мечом

**Пошаговая валидация:**
1. **Выбор действия:** “Атака мечом” (requires_physical_form: Corporeal)
2. **Цель:** “Гоблин” (Alive, Humanoid, Corporeal, Enemy)
3. **Валидация совместимости:** ✅
4. **Проверка доступности:** ✅ (воин владеет мечом)
5. **Расчет финальной стоимости:**
- Базовая: 1 ООД
- Состояние “Усталость”: +1 к стоимости ООД
- Финальная: 2 ООД
6. **Проверка ресурсов:** нужно 2 ООД → доступно 2 ООД ✅
7. **Резервирование:** 2 ООД заморожены, недоступны для других действий
8. **UI-отклик:** Действие готово к выполнению, UI показывает финальную стоимость (2 ООД)
9. **При выполнении:** 2 ООД списываются, резерв освобождается
10. **При отмене:** зарезервированные ресурсы возвращаются

### Пример 4: Кастомная валидация

**Сценарий:** Использование заклинания “Призыв элементаля” в зоне антимагии

**Пошаговая валидация:**
1. **Выбор действия:** “Призыв элементаля” (базовая стоимость: 5 маны, 1 ООД)
2. **Цель:** не требуется (заклинание на область)
3. **Валидация совместимости:** ✅
4. **Проверка доступности:** ✅
5. **Проверка ресурсов:** ✅ (достаточно маны)
6. **Кастомная валидация:**
- Проверка локации: игрок в “Зоне антимагии”
- Правило: магические заклинания запрещены ❌
7. **Результат:** Валидация провалена на кастомном этапе
8. **UI-отклик:** “Магия подавлена в этой области”, действие недоступно

**Примеры валидации:**
- Нельзя атаковать союзника (если не предусмотрено)
- Нельзя использовать воскрешение на живого персонажа
- Нельзя применить заклинание без достаточного количества маны

### Категории действий

### По влиянию на игровой процесс

- **Боевые действия** (атака, защита, заклинания)
- **Движение и навигация**
- **Взаимодействие с объектами**
- **Социальные действия** (диалоги, торговля)
- **Управление ресурсами**

### По стоимости ресурсов

- **Бесплатные действия** (простые взаимодействия)
- **Действия основных очков** (атаки, сложные заклинания)
- **Действия дополнительных очков** (использование предметов)
- **Действия полного хода** (требуют всех очков действий)
