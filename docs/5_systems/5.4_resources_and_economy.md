# 5.3 Ресурсы и экономика

**Определение:** Система управления персональными атрибутами акторов - здоровьем, энергией, очками действий и другими характеристиками, которые могут изменяться в процессе игры.

### Предоставляет другим системам
- Универсальную систему хранения расходуемых значений
- Очки действий как ресурс
- Мана, здоровье и другие жизненные ресурсы
- Валюты и опыт
- Проверку наличия и списание ресурсов

---

### Базовые концепции

### Ресурс (Resource)

**Определение:** Персональный атрибут актора - числовое значение, которое может изменяться в процессе игры и имеет определенные правила поведения.

**Примеры ресурсов:**
- Здоровье, мана, энергия - жизненные показатели
- Очки действий - игровые ресурсы для выполнения действий  
- Усталость, голод - состояния персонажа
- Вдохновение, удача - специальные атрибуты

**Компоненты ресурса у актора:**
- **Тип ресурса** - ссылка на ResourceDefinition
- **Текущее значение** - актуальное количество ресурса
- **Максимальное значение** - верхний предел (если задан в типе)
- **Минимальное значение** - нижний предел (обычно 0)

### ResourceDefinition структура

**ScriptableObject описание:**
```
ResourceDefinition : ScriptableObject {
    id: string                      // Уникальный идентификатор ресурса
    displayName: string             // Название для UI
    hasMaxValue: bool               // Есть ли ограничение сверху
    defaultMaxValue: int            // Базовое максимальное значение (если hasMaxValue = true)
    minValue: int                   // Минимальное значение (обычно 0)
    canExceedMax: bool              // Может ли временно превысить максимум
}
```

### Техническая реализация

### Компоненты системы

**ResourceManager** - основной компонент системы:
- Управление регистрацией типов ресурсов
- Предоставление глобального API для операций с ресурсами
- Валидация типов ресурсов

**ActorResourceContainer** - компонент актора:
- Хранение текущих значений ресурсов актора
- Применение операций изменения ресурсов
- Валидация операций согласно правилам типов

**ResourceRegistry** - реестр типов ресурсов:
- Словарь зарегистрированных ResourceDefinition
- Валидация определений ресурсов
- Предоставление информации о типах ресурсов

### Структуры данных

### ActorResourceContainer структура

**Хранение ресурсов актора:**
```
ActorResourceContainer : MonoBehaviour {
    resources: Dictionary<string, ResourceInstance>    // Ресурсы по типу (ResourceDefinition.id)
    maxValueOverrides: Dictionary<string, int>          // Переопределения максимальных значений
    isInitialized: bool                                 // Завершена ли инициализация
}
```

### ResourceInstance структура

**Экземпляр ресурса у актора:**
```
ResourceInstance {
    resourceType: ResourceDefinition    // Ссылка на тип ресурса
    currentValue: int                   // Текущее значение
    isLocked: bool                      // Заблокирован ли ресурс для изменений
}
```

### Алгоритмы работы с ресурсами

### Операции изменения

**Алгоритм добавления ресурса:**
1. **Проверка блокировки** - ресурс не должен быть заблокирован
2. **Расчет нового значения** - currentValue + amount
3. **Применение ограничений** - проверка максимального значения если hasMaxValue = true
4. **Обновление значения** - установка нового значения
5. **Генерация события** - OnResourceChanged

**Алгоритм вычитания ресурса:**
1. **Проверка блокировки** - ресурс не должен быть заблокирован
2. **Расчет нового значения** - currentValue - amount
3. **Применение ограничений** - проверка минимального значения
4. **Обновление значения** - установка нового значения
5. **Генерация события** - OnResourceChanged

### Система резервирования

**Алгоритм резервирования ресурса:**
1. **Проверка доступности** - currentValue >= amount
2. **Временная блокировка** - установка isLocked = true
3. **Резервирование** - вычитание amount без генерации события
4. **Возврат токена** - создание ReservationToken для отката или подтверждения

**Алгоритм подтверждения резервирования:**
1. **Валидация токена** - токен должен быть активным
2. **Генерация события** - OnResourceChanged с окончательным значением
3. **Снятие блокировки** - isLocked = false
4. **Инвалидация токена** - токен больше не действителен

### API системы

### Основные методы ResourceManager

**Управление типами ресурсов:**
- `ResourceManager.RegisterResourceType(ResourceDefinition resourceDef)` → bool
- `ResourceManager.GetResourceType(string resourceId)` → ResourceDefinition
- `ResourceManager.IsResourceTypeRegistered(string resourceId)` → bool

### Основные методы ActorResourceContainer

**Управление ресурсами:**
- `ActorResourceContainer.AddResource(string resourceId, int amount)` → bool
- `ActorResourceContainer.SubtractResource(string resourceId, int amount)` → bool
- `ActorResourceContainer.SetResource(string resourceId, int value)` → bool
- `ActorResourceContainer.SetMaxResource(string resourceId, int maxValue)` → bool

**Проверка ресурсов:**
- `ActorResourceContainer.GetResourceValue(string resourceId)` → int
- `ActorResourceContainer.GetMaxResourceValue(string resourceId)` → int
- `ActorResourceContainer.HasResource(string resourceId, int amount)` → bool

**Резервирование ресурсов:**
- `ActorResourceContainer.ReserveResource(string resourceId, int amount)` → ReservationToken
- `ActorResourceContainer.ConfirmReservation(ReservationToken token)` → bool
- `ActorResourceContainer.CancelReservation(ReservationToken token)` → bool

### Результаты операций

**ReservationToken:**
```
ReservationToken {
    resourceId: string
    amount: int
    isValid: bool
    timestamp: float
}
```

### Инициализация системы

### Загрузка типов ресурсов

**Процесс инициализации ResourceManager:**
1. **Загрузка ResourceRegistry** - получение списка ResourceDefinition от разработчика
2. **Валидация определений** - проверка уникальности ID и корректности параметров
3. **Регистрация типов** - создание словаря для быстрого доступа O(1)

### Инициализация ActorResourceContainer

**Процесс инициализации актора:**
1. **Получение начальных ресурсов** - список ResourceDefinition из Inspector или ResourceProfile
2. **Создание экземпляров** - создание ResourceInstance для каждого типа ресурса
3. **Установка начальных значений** - currentValue = defaultMaxValue (если hasMaxValue = true) или заданное значение
4. **Валидация ресурсов** - проверка что все типы ресурсов зарегистрированы в ResourceManager
5. **Установка isInitialized = true** - система готова к работе

### События системы

**События изменения ресурсов:**
- **OnResourceChanged** - значение ресурса изменилось
- **OnResourceDepleted** - ресурс достиг минимального значения
- **OnResourceMaxed** - ресурс достиг максимального значения
- **OnResourceTypeRegistered** - новый тип ресурса зарегистрирован

**Структура события:**
```
ResourceEvent {
    actor: Actor
    resourceId: string
    oldValue: int
    newValue: int
    changeType: ResourceChangeType  // Added, Subtracted, Set
    timestamp: float
}
```

### Примеры использования

### Конфигурация ресурсов

**Здоровье (ограниченный ресурс):**
```
HealthResource: {
    id: "health"
    hasMaxValue: true
    defaultMaxValue: 100
    minValue: 0
    canExceedMax: false
}
```

**Энергия/Мана (ограниченный ресурс):**
```
EnergyResource: {
    id: "energy"
    hasMaxValue: true
    defaultMaxValue: 10
    minValue: 0
    canExceedMax: false
}
```

**Очки действий (ограниченный ресурс):**
```
ActionPointsResource: {
    id: "action_points"
    hasMaxValue: true
    defaultMaxValue: 1
    minValue: 0
    canExceedMax: false
}
```

**Опыт (неограниченный ресурс):**
```
ExperienceResource: {
    id: "experience"
    hasMaxValue: false
    minValue: 0
    canExceedMax: true  // Не актуально, так как hasMaxValue = false
}
```

### Ограничения и особенности

**Архитектурные решения:**
- ResourceDefinition как ScriptableObjects для удобства настройки в редакторе
- Разделение определений типов (ResourceManager) и экземпляров у акторов (ActorResourceContainer)
- Система резервирования для предотвращения race conditions при расходовании ресурсов
- Простая система хранения и операций без дополнительной логики

**Текущие ограничения:**
- Только целочисленные значения ресурсов
- Статический набор типов ресурсов (регистрируются при инициализации)
- Персональные атрибуты акторов (физические предметы = ответственность системы инвентаря)
- Только базовые операции (восстановление = ответственность механик)
