# 5.5 Система состояний

**Определение:** Система управления временными эффектами, применяемыми к акторам. Отслеживает время жизни состояний и генерирует события для других систем.

### Зависимости
- **Использует системы:** 5.1 (Теги), 5.3 (Ресурсы), 5.4 (Характеристики)
- **Используется системами:** 5.7 (Ходы), 5.8 (Действия), 6.1 (Механика боя)

### Предоставляет другим системам
- Временные эффекты и модификации
- Модификацию тегов акторов
- Изменение доступных действий
- Модификацию стоимости действий
- Периодические эффекты (регенерация, урон)

### Базовые концепции

### Состояние (Status)

**Определение:** Временный эффект, применяемый к актору с определенным временем жизни.

**Примеры состояний:**
- Отравление, кровотечение - урон со временем
- Благословение, ускорение - временные улучшения
- Оглушение, сон - ограничения действий
- Невидимость, полет - изменения свойств

**Компоненты состояния у актора:**
- **Тип состояния** - ссылка на StatusDefinition
- **Оставшееся время** - количество ходов/раундов до окончания
- **Источник** - кто/что применил состояние (опционально)

### StatusDefinition структура

**ScriptableObject описание:**
```
StatusDefinition : ScriptableObject {
    id: string                      // Уникальный идентификатор состояния
    displayName: string             // Название для UI
    description: string             // Описание эффекта для UI
    duration: int                   // Длительность состояния
    durationType: DurationType      // Тип отсчета времени
}
```

### DurationType enum

**Типы отсчета времени:**
- `ActorTurns` - отсчитывается в ходах конкретного актора
- `Rounds` - отсчитывается в полных раундах всех участников
- `Permanent` - не истекает автоматически

### Техническая реализация

### Компоненты системы

**StatusManager** - основной компонент системы:
- Управление регистрацией типов состояний
- Обработка событий времени от системы ходов
- Предоставление глобального API для работы с состояниями

**ActorStatusContainer** - компонент актора:
- Хранение активных состояний конкретного актора
- Применение политик наложения состояний
- Отслеживание времени жизни состояний

**StatusRegistry** - реестр типов состояний:
- Словарь зарегистрированных StatusDefinition
- Валидация определений состояний

### Структуры данных

### ActorStatusContainer структура

**Хранение состояний актора:**
```
ActorStatusContainer : MonoBehaviour {
    activeStatuses: List<StatusInstance>        // Активные состояния
    statusLookup: Dictionary<string, int>       // Быстрый поиск по ID состояния
    isInitialized: bool                         // Завершена ли инициализация
}
```

### StatusInstance структура

**Экземпляр состояния у актора:**
```
StatusInstance {
    statusType: StatusDefinition    // Ссылка на тип состояния
    remainingDuration: int          // Оставшееся время
    source: string                  // Источник состояния (опционально)
    appliedAt: float               // Время применения
}
```

### Алгоритмы работы с состояниями

### Применение состояния

**Алгоритм применения состояния:**
1. **Валидация StatusDefinition** - проверка что тип состояния зарегистрирован
2. **Проверка существующего состояния** - поиск состояния того же типа
3. **Замена состояния** - если состояние уже есть, удалить старое
4. **Создание StatusInstance** - новый экземпляр с полной длительностью
5. **Добавление в контейнер** - добавление в activeStatuses и обновление индексов
6. **Генерация события** - OnStatusApplied

### Удаление состояния

**Алгоритм удаления состояния:**
1. **Поиск состояния** - по ID или конкретному экземпляру
2. **Удаление из контейнера** - удаление из activeStatuses и индексов
3. **Генерация события** - OnStatusRemoved

### Обновление времени

**Алгоритм обновления длительности:**
1. **Получение события времени** - от системы ходов (ActorTurnEnd/RoundEnd)
2. **Фильтрация состояний** - найти состояния с соответствующим durationType
3. **Уменьшение счетчиков** - remainingDuration -= 1
4. **Проверка истечения** - удалить состояния с remainingDuration <= 0
5. **Генерация событий** - OnStatusExpired для истекших состояний

### Зависимости от других систем

### Система ходов (обязательная зависимость)

**Обоснование:** Система состояний использует события системы ходов для отслеживания времени жизни состояний.

**Используемые артефакты:**
- Подписка на `OnTurnEnd` для уменьшения счетчиков ActorTurns состояний
- Подписка на `OnRoundEnd` для уменьшения счетчиков Rounds состояний

### API системы

### Основные методы StatusManager

**Управление типами состояний:**
- `StatusManager.RegisterStatusType(StatusDefinition statusDef)` → bool
- `StatusManager.GetStatusType(string statusId)` → StatusDefinition
- `StatusManager.IsStatusTypeRegistered(string statusId)` → bool

**Глобальные операции:**
- `StatusManager.FindActorsWithStatus(string statusId)` → List<Actor>

### Основные методы ActorStatusContainer

**Управление состояниями:**
- `ActorStatusContainer.ApplyStatus(string statusId, string source = "")` → bool
- `ActorStatusContainer.RemoveStatus(string statusId)` → bool
- `ActorStatusContainer.RemoveAllStatusesBySource(string source)` → int
- `ActorStatusContainer.ClearAllStatuses()` → void

**Проверка состояний:**
- `ActorStatusContainer.HasStatus(string statusId)` → bool
- `ActorStatusContainer.GetRemainingDuration(string statusId)` → int
- `ActorStatusContainer.GetActiveStatuses()` → List<StatusInstance>

**Управление временем:**
- `ActorStatusContainer.ProcessTurnEnd()` → void (вызывается StatusManager)
- `ActorStatusContainer.ProcessRoundEnd()` → void (вызывается StatusManager)

### Инициализация системы

### Загрузка типов состояний

**Процесс инициализации StatusManager:**
1. **Загрузка StatusRegistry** - получение списка StatusDefinition от разработчика
2. **Валидация определений** - проверка уникальности ID и корректности параметров
3. **Регистрация типов** - создание словаря для быстрого доступа O(1)
4. **Подписка на события ходов** - регистрация обработчиков времени

### Инициализация ActorStatusContainer

**Процесс инициализации актора:**
1. **Получение начальных состояний** - список StatusDefinition из Inspector (если есть)
2. **Валидация состояний** - проверка что все типы состояний зарегистрированы
3. **Создание экземпляров** - создание StatusInstance для начальных состояний
4. **Построение индексов** - создание statusLookup для быстрого поиска
5. **Установка isInitialized = true** - система готова к работе

### События системы

**События жизненного цикла состояний:**
- **OnStatusApplied** - состояние применено к актору
- **OnStatusRemoved** - состояние удалено у актора
- **OnStatusExpired** - состояние истекло по времени

**Структура события:**
```
StatusEvent {
    actor: Actor
    statusId: string
    statusInstance: StatusInstance
    eventType: StatusEventType    // Applied, Removed, Expired
    source: string               // Источник изменения
    timestamp: float
}
```

### Примеры использования

### Конфигурация состояний

**Отравление (временный урон):**
```
PoisonStatus: {
    id: "poisoned"
    duration: 3
    durationType: ActorTurns
}
```

**Оглушение (кратковременное ограничение):**
```
StunStatus: {
    id: "stunned"
    duration: 1
    durationType: ActorTurns
}
```

**Благословение (длительный бафф):**
```
BlessStatus: {
    id: "blessed"
    duration: 5
    durationType: Rounds
}
```

**Постоянное состояние:**
```
CursedStatus: {
    id: "cursed"
    duration: 0
    durationType: Permanent
}
```

### Примеры интеграции через события

**Система ресурсов реагирует на отравление:**
```csharp
StatusManager.OnStatusApplied += (statusEvent) => {
    if (statusEvent.statusId == "poisoned") {
        // Применить урон каждый ход
        SchedulePeriodicDamage(statusEvent.actor, 5);
    }
};
```

**Система действий блокирует при оглушении:**
```csharp
StatusManager.OnStatusApplied += (statusEvent) => {
    if (statusEvent.statusId == "stunned") {
        // Блокировать все действия кроме "пропустить ход"
        ActionSystem.BlockAllActions(statusEvent.actor);
    }
};
```

### Ограничения и особенности

**Архитектурные решения:**
- StatusDefinition как ScriptableObjects для удобства настройки в редакторе
- Разделение определений типов (StatusManager) и экземпляров у акторов (ActorStatusContainer)
- Простая система счетчиков времени через события системы ходов
- Генерация событий для интеграции с другими системами без прямой связанности

**Текущие ограничения:**
- Только простые временные счетчики (ходы актора, раунды, постоянные)
- Статический набор типов состояний (регистрируются при инициализации)
- Система не применяет эффекты состояний (это ответственность других систем)
- Только одно состояние каждого типа на актора (повторное применение заменяет существующее)
