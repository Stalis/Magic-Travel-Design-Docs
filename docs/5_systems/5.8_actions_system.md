# 5.8 Система действий

**Определение:** Действием является любая активность, которую может выполнить актор: от простого движения до сложных заклинаний.

### Предоставляет другим системам
- Универсальную систему выполнения всех игровых действий
- Валидацию совместимости действий и целей
- Расчет стоимости действий с модификаторами
- Резервирование и списание ресурсов

---

### Базовые концепции

#### Действие (Action)

**Определение:** Структура данных, описывающая конкретную активность, которую может выполнить актор.

**Компоненты действия:**
- **ActionDefinition** - ScriptableObject с описанием действия
- **Исполнитель** - актор, выполняющий действие
- **Цель** - Action Target для применения действия (опционально)
- **Параметры** - дополнительные данные для выполнения (координаты, объекты)

#### ActionDefinition структура

**ScriptableObject описание:**
```
ActionDefinition : ScriptableObject {
    id: string                                    // Уникальный идентификатор
    displayName: string                          // Название для UI
    baseResourceCosts: Dictionary<string, int>   // Базовая стоимость ресурсов
    targetRequirements: TargetRequirements      // Требования к цели
    executionHandler: IActionExecutionHandler   // Обработчик выполнения
    customValidator: IActionValidator           // Кастомный валидатор (опционально)
}
```

#### TargetRequirements структура

**Требования к цели:**
```
TargetRequirements {
    requiredTags: List<string>     // Цель должна иметь эти теги
    excludedTags: List<string>     // Цель не должна иметь эти теги
    requiresTarget: bool           // Нужна ли цель для действия
}
```

### Интерфейсы обработчиков

**IActionExecutionHandler:**
```
interface IActionExecutionHandler {
    ExecutionResult Execute(Actor performer, Actor target, Dictionary parameters)
}
```

**IActionValidator:**
```
interface IActionValidator {
    ValidationResult Validate(Actor performer, Actor target, Dictionary parameters)
}
```

### Техническая реализация

#### Компоненты системы

**ActionManager** - основной компонент системы:
- Загрузка и регистрация ActionDefinition при инициализации
- Предоставление API для валидации и выполнения действий
- Управление резервированием ресурсов

**ActionValidator** - компонент валидации:
- Проверка совместимости действия с целью
- Валидация наличия ресурсов у исполнителя
- Вызов кастомных валидаторов

**ActionExecutor** - компонент выполнения:
- Резервирование и списание ресурсов
- Вызов обработчиков выполнения
- Генерация событий жизненного цикла

#### Алгоритм валидации

**Последовательность проверок:**
1. **Валидация цели** - соответствует ли цель требованиям через систему тегов
2. **Валидация ресурсов** - достаточно ли ресурсов у исполнителя через систему ресурсов
3. **Кастомная валидация** - вызов пользовательского валидатора если он задан
4. **Результат** - Success/Failed с описанием причины отказа

#### Алгоритм выполнения

**Процесс выполнения действия:**
1. **Валидация** - полная проверка возможности выполнения
2. **Резервирование ресурсов** - временная блокировка необходимых ресурсов
3. **Генерация OnActionStart** - уведомление о начале выполнения
4. **Вызов ExecutionHandler** - применение эффектов действия
5. **Списание ресурсов** - окончательное списание зарезервированных ресурсов
6. **Генерация OnActionComplete** - уведомление о завершении

### API системы

### Основные методы ActionManager

**Валидация действий:**
- `ActionManager.ValidateAction(ActionDefinition action, Actor performer, Actor target)` → ValidationResult
- `ActionManager.CanPerformAction(string actionId, Actor performer, Actor target)` → bool

**Выполнение действий:**
- `ActionManager.ExecuteAction(ActionDefinition action, Actor performer, Actor target, Dictionary parameters)` → ExecutionResult
- `ActionManager.ExecuteActionById(string actionId, Actor performer, Actor target, Dictionary parameters)` → ExecutionResult

**Управление определениями:**
- `ActionManager.GetActionDefinition(string actionId)` → ActionDefinition
- `ActionManager.GetAvailableActions(Actor performer)` → List<ActionDefinition>

### Результаты операций

**ValidationResult:**
```
ValidationResult {
    isValid: bool
    failureReason: string
    failedAt: ValidationStage  // На каком этапе провалилась валидация
}
```

**ExecutionResult:**
```
ExecutionResult {
    success: bool
    message: string
    modifiedActors: List<Actor>  // Какие акторы были затронуты действием
}
```

### События системы

**События жизненного цикла действий:**
- **OnActionValidated** - действие прошло валидацию
- **OnActionStart** - начало выполнения действия
- **OnActionComplete** - действие успешно завершено
- **OnActionFailed** - действие провалилось при выполнении
- **OnActionCancelled** - действие отменено пользователем

**Структура события:**
```
ActionEvent {
    actionId: string
    performer: Actor
    target: Actor (nullable)
    timestamp: float
    additionalData: Dictionary
}
```

### Инициализация системы

### Регистрация ActionDefinition

**Процесс инициализации:**
1. **Получение списка действий** - разработчик предоставляет список ActionDefinition через Inspector или конфигурационный файл
2. **Валидация определений** - проверка корректности данных каждого действия (уникальность ID, валидность требований)
3. **Регистрация** - добавление действий в словарь по ID для быстрого доступа O(1)
4. **Инициализация обработчиков** - подготовка IActionExecutionHandler и IActionValidator

### Категории действий

**Классификация по целям:**
- **Targeted** - требуют конкретную цель-актора (атака врага, лечение союзника)
- **Positional** - требуют координаты клетки (заклинание в область, телепортация)

### Примеры ActionDefinition

**Атака мечом (Targeted):**
```
{
    id: "attack_sword"
    baseResourceCosts: { "action_points": 1 }
    targetRequirements: { 
        requiredTags: ["corporeal"], 
        excludedTags: ["ally"],
        requiresTarget: true 
    }
}
```

**Применение зелья лечения (Targeted):**
```
{
    id: "use_healing_potion"
    baseResourceCosts: { "healing_potion": 1, "bonus_action_points": 1 }
    targetRequirements: { 
        requiredTags: ["alive", "organic"], 
        excludedTags: ["undead"],
        requiresTarget: true  // Можно применить на себя или союзника
    }
}
```

**Огненный шар (Positional):**
```
{
    id: "fireball"
    baseResourceCosts: { "mana": 3, "action_points": 1 }
    targetRequirements: { 
        requiredTags: [], 
        excludedTags: [],
        requiresTarget: false  // Цель - координаты клетки
    }
}
```

### Ограничения и особенности

**Архитектурные решения:**
- ActionDefinition как ScriptableObjects для удобства создания контента
- Разделение валидации и выполнения для модульности
- Резервирование ресурсов для предотвращения race conditions

**Текущие ограничения:**
- Одно действие за раз на актора (нет параллельного выполнения)
- Статический набор ActionDefinition (загружается при инициализации)
- Простая система приоритетов для конфликтующих действий
