# 5.2 Система ходов

**Определение:** Система управления временем и очередностью действий в игре через два режима работы: строгий пошаговый режим и режим реального времени.

### Базовые концепции

### Ход (Turn)

**Определение:** Основная единица времени, в течение которой Turn Actor может выполнить свои действия.

**Техническая реализация:** Каждый ход представляет собой корутину, которая запускается системой ходов и завершается по сигналу от актора.

**Структура хода:**
1. Начало хода (триггер событий начала хода для других систем)
2. Фаза действий (выполнение корутины актора)
3. Завершение хода (завершение корутины, триггер событий конца хода)

### Раунд (Round)

**Определение:** Один полный проход по всем активным Turn Actor в строгом режиме, либо один цикл в режиме реального времени.

**Структура раунда:**
1. Определение списка активных акторов
2. Выполнение ходов (различается по режимам)
3. Триггер события конца раунда для других систем

### Turn Actor

**Определение:** Компонент Unity, который вручную размещается на игровых объектах для обозначения сущностей, участвующих в системе ходов.

**Свойства:**
- **Инициатива** - числовое значение для определения порядка ходов в строгом режиме
- **Корутина хода** - основной метод выполнения действий актора
- **Активность** - может ли актор участвовать в текущем раунде

### Режимы работы системы

### Строгий режим ходов (Strict Mode)

**Характеристики:**
- Система ходов управляет очередностью выполнения
- Ходы выполняются строго последовательно
- Каждый актор завершает свою корутину перед переходом к следующему

**Алгоритм работы:**
1. Сортировка списка Turn Actor по инициативе (по убыванию)
2. Последовательный запуск корутин ходов
3. Ожидание завершения корутины каждого актора
4. Переход к следующему актору в списке
5. После прохода всех акторов - триггер конца раунда

**Особенности для игрока:**
- Единственный актор с интерактивным управлением хода
- Корутина завершается по внутреннему событию игрока
- Система ходов ожидает действий игрока неограниченное время

### Режим реального времени (Real-Time Mode)

**Характеристики:**
- Все ходы (кроме игрока) запускаются одновременно с фиксированным интервалом
- По умолчанию: каждые 2 секунды (параметр настраиваемый)
- Игрок может действовать в любое время

**Алгоритм работы:**
1. Пакетный запуск корутин всех ИИ-акторов каждые N секунд
2. Игрок действует независимо от циклов ИИ
3. Возможна рассинхронизация количества ходов между участниками

### Переключение режимов

### Управление режимами

**Техническая реализация:** 
Переключение управляется через ScriptableVariable (булевое значение), которую может изменять любая система или скрипт.

**Триггеры переключения:**
- Действия игрока
- Механика боя (автоматическое включение строгого режима)
- Игровые события и сценарии
- Команды разработчика для тестирования

### Алгоритм переключения Real-Time → Strict

1. Получение события изменения ScriptableVariable
2. Ожидание завершения всех текущих ходов ИИ-акторов
3. Выключение real-time контроллера
4. Включение strict контроллера
5. Сортировка списка акторов по инициативе
6. Запуск строгой последовательности ходов

### Алгоритм переключения Strict → Real-Time

1. Получение события изменения ScriptableVariable
2. Выключение strict контроллера
3. Включение real-time контроллера
4. Немедленное освобождение игрока для действий
5. ИИ-акторы ожидают следующего цикла для синхронизации

### Управление участниками

### Регистрация Turn Actor

**Автоматическая регистрация:**
- Turn Actor компоненты автоматически регистрируются при активации
- Используется стандартный Unity lifecycle (Awake/OnEnable)
- Система поддерживает простой список всех активных акторов

**Ручная настройка:**
- Разработчики вручную размещают Turn Actor компоненты на нужных объектах
- Каждый компонент настраивается индивидуально в Inspector

### Динамическое управление

**Добавление участников:**
- Новые акторы добавляются в конец списка
- В строгом режиме: участвуют в следующем раунде
- В real-time режиме: включаются в следующий цикл

**Удаление участников:**
- Акторы удаляются из списка при деактивации
- Текущие корутины завершаются естественным образом
- Система адаптируется к изменению состава участников

**Примечание:** Унифицированный подход к регистрации/исключению пока не определен и требует дальнейшей проработки.

### События системы ходов

**Триггеры для других систем:**
- **Начало хода актора** - для применения эффектов начала хода
- **Конец хода актора** - для применения эффектов конца хода  
- **Конец раунда** - для обновления состояний, счетчиков времени
- **Переключение режимов** - для адаптации поведения других систем

### Параметры системы

**Настраиваемые значения:**
- Интервал ходов в real-time режиме (по умолчанию: 2 секунды)
- Правила сортировки по инициативе
- Поведение при равных значениях инициативы

### Ограничения и особенности

**Текущие ограничения:**
- Отсутствие очереди ходов в классическом понимании
- Не реализован унифицированный подход к регистрации участников
- Простая модель событий (может требовать расширения)

**Архитектурные решения:**
- Приоритет простоты над сложностью
- Делегирование ответственности другим системам
- Фокус на управлении временем, а не на игровой логике
