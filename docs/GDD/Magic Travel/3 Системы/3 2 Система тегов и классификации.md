# 3.2 Система тегов и классификации

**Определение:** Единая система маркировки акторов через теги с категориями и политиками для автоматической валидации совместимости действий и организации игрового контента.

### Структура тега

**Компоненты тега:**
- **ID** - уникальный строковый идентификатор (например, “large”, “humanoid”, “on_fire”)
- **Категория** - группа, определяющая поведение и политики тега (например, “size”, “type”, “temporary_state”)
- **Значение** - опциональные дополнительные данные (например, числовое значение урона для “poison:5”)

**Формат записи:**
- Простой тег: `size:large`, `type:humanoid`
- Тег со значением: `poison:5`, `strength_buff:+3`

### Политики категорий

### Single (единичная)

**Описание:** В категории может быть только один активный тег. При добавлении нового тега старый автоматически удаляется.

**Примеры категорий:**
- `size` (tiny, small, medium, large, huge, gargantuan)
- `life_state` (alive, dead, unconscious)
- `allegiance` (ally, enemy, neutral)
- `physical_form` (corporeal, incorporeal)

**Поведение:** `size:small` + `size:large` → остается `size:large`

### Multiple (множественная)

**Описание:** В категории может быть несколько активных тегов одновременно.

**Примеры категорий:**
- `material` (organic, mechanical, magical, ethereal)
- `temporary_state` (stunned, poisoned, blessed, cursed)
- `resistance` (fire_resistant, cold_resistant, magic_resistant)
- `movement` (flying, swimming, burrowing)

**Поведение:** `material:organic` + `material:magical` → остаются оба

### Immutable (неизменяемая)

**Модификатор:** Теги этой категории нельзя изменять после создания актора.

**Примеры применения:**
- `type` (humanoid, beast, undead, construct) - базовый тип существа
- `base_size` - исходный размер до модификаций

**Поведение:** Попытка изменить immutable тег игнорируется с предупреждением

### Mutable (изменяемая)

**Модификатор:** Теги можно свободно добавлять/удалять в процессе игры.

**Примеры применения:**
- `life_state` - может меняться с alive на dead
- `temporary_state` - эффекты появляются и исчезают

### Валидация тегов

### Первичная валидация при создании

При создании актора система автоматически приводит список тегов к рабочему состоянию:

**Конфликты Single категорий:**

```
Исходные теги: [size:large, size:small, type:human, allegiance:ally]
После валидации: [size:small, type:human, allegiance:ally]
// Оставлен последний тег из категории size
```

**Дублирование тегов:**

```
Исходные теги: [material:organic, material:organic, state:tired]
После валидации: [material:organic, state:tired]
// Удалены дубликаты
```

**Неизвестные категории:**

```
Исходные теги: [size:large, invalid_category:test]
После валидации: [size:large]
// Неизвестная категория удалена с предупреждением
```

### Валидация политик

**Single категории:** Автоматическое замещение при конфликтах
**Multiple категории:** Проверка на дублирование ID
**Immutable категории:** Блокировка изменений после создания

### Предвалидация в редакторе

**Рекомендация для Unity:** Создать Editor Script для валидации акторов на этапе разработки:
- Проверка корректности тегов в prefab’ах и ScriptableObject’ах
- Предупреждения о конфликтующих тегах при сохранении
- Автоматическое исправление простых ошибок

**Альтернатива:** Валидация при загрузке уровня в Development Build с подробными логами ошибок.

### Примеры категорий и политик

**Single + Immutable (неизменяемые базовые свойства):**

```
type:humanoid, type:beast, type:construct
// Определяется при создании, не меняется в игре
```

**Single + Mutable (изменяемые состояния):**

```
life_state:alive, life_state:dead, life_state:unconscious
size:small, size:medium, size:large
// Только один активный, может меняться в процессе игры
```

**Multiple + Mutable (накапливающиеся свойства):**

```
material:organic + material:magical
movement:ground + movement:flying
temporary_state:stunned + temporary_state:poisoned
// Могут быть активны одновременно, изменяются динамически
```

### Использование в системах

**Создание новых категорий:**
Каждая игровая система может определить собственные категории тегов согласно своим потребностям.

**Пример расширения диалоговой системой:**

```
Категория: dialog_state (Single + Mutable)
Теги: met_before, knows_secret, hostile, friendly, suspicious
```

**Пример расширения системой крафта:**

```
Категория: craft_material (Multiple + Mutable)
Теги: wood, metal, stone, leather, fabric, gem
```

### Технические принципы

**Производительность:**
- Теги хранятся в виде хеш-сетов по категориям для быстрого поиска
- Валидация выполняется только при создании и модификации

**Расширяемость:**
- Новые категории добавляются без изменения core системы
- Политики категорий настраиваются через конфигурационные файлы

**Отладка:**
- Подробное логирование процесса валидации
- Editor-инструменты для инспектирования тегов акторов
