# 3.6 Система GridMap

### Основные принципы

**Определение:** GridMap - система пространственной организации игрового мира через дискретную сетку клеток с геймплейными свойствами, не связанными с визуальным представлением.

### Структура системы

**Иерархия компонентов:**
1. **Карта (Map)** - корневой контейнер всего уровня
2. **Локация (Location)** - крупная область карты с собственным названием
3. **Комната (Room)** - логический контейнер внутри локации для упрощения левел-дизайна
4. **Клетка (Cell)** - минимальная единица пространства с координатами
5. **Стена (Wall)** - барьер между клетками по четырем направлениям

**Принцип разделения:**
- **Геймплейная логика**: клетки и стены существуют как эфемерные данные
- **Визуальное представление**: полностью независимо от сеточной структуры
- **Интерактивные объекты**: размещаются в свободной форме, не привязаны к сетке

### Система координат

**Координатная сетка:**
- Используется двумерная система координат (X, Y)
- Каждая клетка имеет уникальные целочисленные координаты
- Координаты определяют позицию в игровом пространстве независимо от визуала

**Направления стен:**
- **Север (North)** - верхняя граница клетки
- **Восток (East)** - правая граница клетки  
- **Юг (South)** - нижняя граница клетки
- **Запад (West)** - левая граница клетки

### Свойства элементов

### Свойства клеток

**isWalkable** - определяет возможность передвижения:
- `true`: актор может занимать эту клетку
- `false`: клетка заблокирована для движения

**isTransparent** - определяет прозрачность для обзора:
- `true`: через клетку проходит линия видимости
- `false`: клетка блокирует обзор

**isPiercable** - определяет проницаемость для снарядов:
- `true`: через клетку могут проходить атаки дальнего боя
- `false`: клетка блокирует дистанционные атаки

### Свойства стен

**Стены наследуют те же свойства** с аналогичной логикой:
- **isWalkable**: можно ли пройти через стену
- **isTransparent**: блокирует ли стена обзор
- **isPiercable**: можно ли стрелять через стену

**Применение свойств стен:**
- Двери: `isWalkable = true, isTransparent = false, isPiercable = false`
- Решетки: `isWalkable = false, isTransparent = true, isPiercable = false`
- Магические барьеры: `isWalkable = false, isTransparent = true, isPiercable = true`

### Система регистрации

### Процесс инициализации

**Этапы запуска системы:**
1. **Сканирование иерархии**: компонент карты обходит дерево объектов сцены
2. **Сбор данных**: извлечение информации о клетках и стенах из компонентов
3. **Создание словаря**: построение структуры данных для быстрого доступа
4. **Валидация**: проверка целостности и корректности данных

**Структура хранения:**
```
Dictionary<Coordinates, CellData>
- Координаты клетки → Данные о клетке + четыре стены
- Быстрый доступ O(1) по координатам
- Централизованное хранение всей геймплейной информации
```

### Взаимодействие с игровыми системами

### Система движения

**Валидация перемещения:**
- Проверка `isWalkable` целевой клетки
- Проверка `isWalkable` стен на пути движения
- Учет направления движения для определения релевантных стен

### Система видимости

**Расчет линии видимости:**
- Трассировка луча между двумя точками
- Проверка `isTransparent` для всех клеток и стен на пути
- Определение видимых областей для акторов

### Система дальнего боя

**Валидация атак:**
- Проверка `isPiercable` для клеток и стен между атакующим и целью
- Определение возможности попадания через препятствия
- Расчет траектории снарядов

### Особенности реализации

### Независимость от визуала

**Принципы разделения:**
- Геймплейная сетка не зависит от 3D-моделей и спрайтов
- Визуальные объекты могут занимать несколько клеток или части клеток
- Возможность изменения визуала без влияния на геймплей

### Гибкость размещения объектов

**Интерактивные элементы:**
- Размещаются в произвольных позициях на сцене
- Не ограничены сеточной структурой
- Могут перекрывать несколько клеток или находиться между ними

### Оптимизация производительности

**Эффективность доступа:**
- Словарная структура обеспечивает быстрый поиск по координатам
- Отсутствие необходимости в поиске по иерархии объектов во время игры
- Кэширование данных при инициализации уровня

### Левел-дизайн

### Иерархическая структура

**Организация контента:**
- **Карта**: глобальный контейнер для всего уровня
- **Локации**: тематические области (например, "Лаборатория", "Склады")
- **Комнаты**: логические подразделения для удобства редактирования

**Преимущества подхода:**
- Упрощение навигации по сложным уровням
- Возможность группировки связанного контента
- Облегчение командной работы над уровнями

### Инструменты разработки

**Редактирование в Unity:**
- Размещение компонентов клеток и стен на сцене
- Визуальная настройка свойств через Inspector
- Предпросмотр сеточной структуры в Scene View

**Валидация данных:**
- Автоматическая проверка целостности при сборке
- Предупреждения о некорректных конфигурациях
- Инструменты отладки для анализа сеточных данных

### Расширяемость системы

### Дополнительные свойства

**Возможности расширения:**
- Добавление новых булевых свойств для специфических механик
- Численные параметры (например, стоимость движения)

### Интеграция с другими системами

**Связь с существующими компонентами:**
- Использование системы тегов для классификации клеток
- Интеграция с системой действий для валидации движения
- Поддержка системы ходов для определения допустимых перемещений

### Технические ограничения

**Рамки системы:**
- Работает только с дискретным пространством
- Требует предварительной настройки сеточной структуры
- Не подходит для полностью свободного движения

**Рекомендации по использованию:**
- Оптимальна для тактических и пошаговых игр
- Подходит для игр с четким разделением на зоны
- Эффективна при необходимости точного контроля пространства
