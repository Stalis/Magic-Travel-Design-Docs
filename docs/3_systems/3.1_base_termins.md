# 3.1 Основные понятия

### Система (System)

**Определение:** Постоянно работающая инфраструктура, предоставляющая абстракции и сервисы для игровых механик.

**Характеристики:**
- **Время жизни:** Существуют постоянно с запуска игры
- **Назначение:** Инфраструктурный слой, "движок" для геймплея
- **Активация:** Всегда доступны и работают
- **Зависимости:** Системы зависят друг от друга
- **Расположение:** Модуль "движка"/библиотека абстракций

**Примеры:** Система тегов, система ходов, система ресурсов, система действий

### Механика (Mechanic)

**Определение:** Геймплейные активности с жизненным циклом, которые используют системы для реализации игрового опыта.

**Характеристики:**
- **Время жизни:** Имеют начало, процесс и завершение
- **Назначение:** Конкретные игровые активности
- **Активация:** Запускаются событиями или действиями игрока
- **Зависимости:** Механики используют системы
- **Расположение:** Геймплейный слой

**Примеры:** Бой, диалоги, торговля, крафт, квесты, отдых

### Критерии определения

**Тест на постоянность:**
- Система: Работает ли это постоянно? ✅
- Механика: Имеет ли это начало и конец? ✅

**Тест на назначение:**
- Система: Предоставляет ли абстракции/сервисы? ✅
- Механика: Реализует ли игровой опыт? ✅

**Тест на активацию:**
- Система: Всегда доступна для использования? ✅
- Механика: Запускается событиями? ✅

### Актор (Actor)

**Определение:** Любой игровой объект, который может участвовать в игровых системах - выполнять действия, быть целью действий, или и то, и другое.

**Принцип работы:**
Каждая игровая система определяет своих акторов - объекты, с которыми эта система может работать. Один и тот же объект может быть актором нескольких систем одновременно.

**Примеры:**
- Персонаж игрока может быть Turn Actor (выполняет ходы), Action Target (может быть целью лечения), Dialog Actor (ведет диалоги)
- Дверь может быть только Action Target (можно открыть/сломать)
- Туман может быть только Turn Actor (рассеивается со временем)

**Технические особенности:**
- Каждый актор имеет набор характеристик и тегов для валидации взаимодействий
- Актор может динамически приобретать или терять возможности участия в системах
- Системы используют классификацию характеристик для определения совместимости

### Игровой сценарий (Game Script)

**Определение:** Записанная программным кодом последовательность действий, которая может быть запущена действиями игрока или другими акторами в зависимости от условий.

**Структура сценария:**
- **Условия активации** (триггеры)
- **Предварительные условия** (preconditions)
- **Последовательность действий**
- **Условия завершения**

**Типы сценариев:**
- Квестовые сценарии
- Боевые события
- Изменения окружения
- Диалоговые системы
- Системы прогрессии
